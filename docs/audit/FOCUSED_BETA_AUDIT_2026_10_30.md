# Focused small-beta audit — working record

Scope: BA-MATE saving, recovery, core workflow and usability, using synthetic test data. This is an ongoing audit, not a beta certification. No APNK requirements, document, diagrams or stakeholder decisions were changed.

## Work preservation and recovery

- Existing automated tests cover recovery ZIPs, missing source originals, partial folder writes, source hash mismatches and conflict rejection. Added a concurrent SQLite test: two simultaneous saves against the same revision result in one save and one conflict, with the winning state retained. This is a backend concurrency test, not a full two-window browser recovery exercise.
- A later live test used a fresh isolated service and synthetic project in two browser tabs. A conflicting save displayed Saving paused and recovery instructions in the first tab; its records-only ZIP was downloaded and restored as a separate project in the other tab. The recovered project showed the synthetic clarification created in the paused window, and the saved answer from before the conflict. This checks one no-source recovery scenario on this Mac, not an automatic merge, source-original recovery, interrupted restore, all project records or other environments. Background saves also occurred during the session; the exact write that won the race was not isolated.
- An unsaved clarification answer now survives navigation within the current application session, shows an unsaved notice and can be discarded. The browser warns before leaving with such a draft. These drafts remain in memory and are not included in recovery ZIPs. See the UI/UX review for the earlier focused test.
- On the same isolated browser run, a new synthetic project and goal were created, the Setup checklist correctly blocked advancement without a reviewed source, and an unsaved answer remained present with its warning after navigating away and back. Its confirming person and answer could then be saved. This is a focused path, not all workflow stages.
- A second isolated project used a synthetic text file: its source was extracted, reviewed and selected, Setup advanced to Discover, and a full ZIP restored separately. The original and restored files had matching SHA-256 hashes; the restored source remained selected and the goal remained at Discover. On the restored test project, a synthetic stakeholder, clarification and requirement were added, a source link verified, the requirement submitted, and the workflow advanced through Clarify, Define and Validate to a self-attested test baseline and completed goal. This verifies one simple manual path, not all approval, concurrency, error or multi-goal cases.
- Connecting or changing a project folder now checks whether the original folder or source records changed while copying; if so, it retains the current project and identifies where the copied files may be found. Missing originals are reported rather than described as copied, and a failed partial copy identifies its destination. Tests simulate changed records, missing originals, write failure and incomplete service receipts. The OS folder picker and these race conditions have not been exercised live across platforms.
- Source imports and reattachment now recheck the project folder and relevant source state before applying copied-file paths, and report an unlinked copy if that check fails. Concurrent file actions on the Sources screen are disabled while one is underway. Component tests cover normal import and folder changes during import or reattachment; OS file and folder races have not been exercised live.
- Browser-folder copies now stop after exhausting the name-collision limit and reuse identical files without rewriting them. Simulated file-handle tests cover both behaviors. These tests do not establish atomic behavior if another process creates or changes a destination between the browser's lookup and write.

## Workflow and assistant

- Competing selected change patches targeting the same field could previously both pass validation and the later patch overwrite the earlier one. Validation now blocks this before acceptance or implementation, with a synthetic regression test. Multiple distinct document blocks remain permitted. Existing tests cover simulated review and baseline dependencies; the new case has not been exercised in a live browser.
- Corrected the change-implementation message when no active goal exists: it now asks the user to start a goal rather than claiming an active workflow returned to Validate. This is a text correction; the full post-completion change journey still needs live verification.
- The assistant drawer no longer clears text typed while a request is running or overwrites it when a request fails. A component test covers typing during a successful delayed response; failure and source-check races still need live checking.
- Change acceptance, implementation and revalidation now recheck their relevant working state when applied and report success only after the resulting state is visible. Tests exercise a changed requirement arriving before acceptance, and a successful acceptance and implementation. This is component-level evidence, not a complete multi-window journey. Other actions, including document synchronization, still require separate review of deferred state-update feedback.
- The workflow page previously showed a disabled “Advance to Approve” action while already at Approve. It now links to goal completion; the approval checklist continues to identify baseline blockers.
- Cancelling Task AI during source verification now prevents a subsequent model request; a project or permission change during verification also prevents sending the stale context. Cancellation during an active model request aborts it and records a cancelled run when its outcome returns. Component tests cover these paths with delayed mocked requests. A cancelled or failed assistant-drawer request now retains its original text for inspection even if the composer contains a newer draft. Live provider cancellation, server-side cancellation and all navigation races remain unqualified.
- Task AI and both chat entry points now check the selected source paths and project context again after their asynchronous source checks; the conversation also checks its messages and attachments. If context changes, no model request is sent and the draft remains. Component tests simulate changed context, and a Task AI test also changes the workspace folder. This does not make the file read and model request atomic or qualify external providers.
- Unsent Ask BA Mate messages are now retained separately by project and conversation during in-app navigation. The composer identifies them as temporary and excluded from backups; leaving or reloading the app triggers the existing unsaved-work warning. A component test checks leaving and returning. Reload, browser-close and full recovery of unsent text remain outside this in-memory mechanism.

## Remaining priorities

Finish keyboard and screen-reader checks and a small analyst pilot. Audit other state-update feedback for deferred callbacks and concurrency. Installation, other platforms, study-service staging and security/privacy review remain unqualified.
